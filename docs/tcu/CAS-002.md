## Objective and boundary

Every imported story receives a decision per category, beginning with cyberattack and crypto.
Adding a category is a policy change with tests, not a code change across packages.

In scope: a category contract alongside the existing signal policy; a classifier run that emits
one decision per category per row; a migration that stores the category with each result; the
review queue filtered by category; calibration of cyberattack against CS79 and CS86; calibration
of crypto against a labelled set the owner provides, or an explicit record that crypto recall is
unmeasured in v0.

Out of scope: round-up or article generation; any change to clustering's grouping rules; a model call,
unless the owner decides at S0 that classification uses one.
