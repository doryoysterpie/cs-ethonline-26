## Objective and boundary

predicate in `@cas/contracts`, `prohibited-text@2`: every code point the running Node reports
as Default_Ignorable_Code_Point but U+FE0E and U+FE0F, with the controls, separators,
interlinear annotation characters and noncharacters the old table named. No consumer keeps a
list of its own. Stored text, the database, the dashboard's display escapes, the body refusal
of drafts, round-ups and articles, the MCP server and the worker's source scanner do not
change.

- Every code point the runtime reports as Default_Ignorable_Code_Point, but U+FE0E and
  U+FE0F, is a hygiene finding in a tracked file, removed by the export, refused by the card's
  contract and removed from the card's display text; the two selectors pass all four.
- The rule exists once; `git grep` finds no other list in the three consumers.
- `corepack pnpm hygiene:fix` removes the default-ignorable characters from tracked files and
  leaves every other finding; it never writes to an existing file, replacing a tracked file by a
  rename after checking on the open handle that it is this checkout's (a link in any component,
  or a file linked from elsewhere, is refused); a concurrent change to the checkout is outside
  its threat model.
