## Objective and boundary

From a persisted selection, read every source in full and write an original article in a tech
reporter's register, editable by the owner alone, exported as copy-ready Markdown.

An article is not a round-up. The model reads the full text of every source of the selected
stories and writes original prose from them: a headline, a standfirst and body paragraphs, each
paragraph citing the sources it rests on.

In scope: a source-reading boundary that fetches the full text of each selected story's URL at
generation time under a fetch policy and extracts text; an owner decision on where fetched text
lives and for how long; the article contract and schema; the reporter register as a versioned,
hashed prompt; D9 parameters revisited for the larger context; the owner-only mechanism from
CAS-004 with `generate:article`; revision storage, editor and export reused from CAS-004; tests
with recorded pages and recorded responses; failure modes for a refused fetch, an unavailable
source, an oversize page and a timeout, where an unavailable source is reported as missing and
never invented around.

Out of scope: the round-up; posting to Substack; images; any fetch that is not for a story in
the selection.

Security necessity: the fetch is a new outbound network boundary from the deployed service.
Without the rules of `docs/FETCH-POLICY.md`, a crafted URL in the feed turns the generator into
a request forger against the hosting network.

## Acceptance

- The owner selects stories, requests an article, and receives an editable article whose every
  paragraph cites sources from the selection.
- A source that could not be fetched appears in a fixed "not read" list and nowhere in the
  prose.
- A URL resolving to a private address is refused with a fixed code and no request is made.
- A non-owner is refused with a fixed code.
- Cost and page counts are recorded as audit events.
- With the key absent the request fails closed and writes nothing.
